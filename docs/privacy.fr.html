Politique de confidentialité de Markleaf

Dernière mise à jour : 26 mai 2026 · S'applique à Markleaf Android v2.x

Principe fondamental

Markleaf est une application de notes Markdown local-first. Elle n'exploite aucun serveur propre et n'envoie jamais de notes, étiquettes, pièces jointes ou métadonnées vers un serveur externe. Les versions distribuées par F-Droid et Google Play n'ont aucune permission android.permission.INTERNET ; la version sideload publiée sur GitHub Releases la déclare pour un seul usage, décrit à la section Réseau.

Informations que Markleaf ne collecte pas

  • Nom, e-mail, contacts, localisation
  • Informations de compte ou de connexion
  • Corps de la note, titre, étiquettes, images jointes, noms de fichiers, métadonnées
  • Statistiques d'utilisation, télémétrie, événements d'analyse, identifiants publicitaires
  • Rapports de plantage ou identifiants d'appareil

Elle ne contient pas non plus d'analyse, de publicité, de suivi, de configuration à distance, de Firebase, ni de SDK de rapport de plantage à code source fermé.

Réseau

Cela dépend d'où vous avez obtenu l'application. Dans les deux cas, aucune donnée de vos notes n'est jamais envoyée.

  • F-Droid et Google Play — aucune permission android.permission.INTERNET, et aucune activité réseau.
  • GitHub Releases (sideload) — déclare deux permissions : une pour la vérification de mise à jour, une pour pouvoir installer la mise à jour que vous choisissez de télécharger. Les deux ne fonctionnent que si vous activez la vérification.
F-Droid / Google Play   INTERNET : aucune · REQUEST_INSTALL_PACKAGES : aucune
GitHub Releases         INTERNET : vérification de mise à jour · REQUEST_INSTALL_PACKAGES : installation après vérification du SHA-256

La vérification de mise à jour dans la version sideload

  • Désactivée par défaut. Rien ne se produit tant que vous ne l'activez pas dans les réglages.
  • Une fois par jour, une seule requête GET vers un fichier JSON statique décrivant la dernière version. Un échec est ignoré en silence.
  • Toucher Télécharger et installer dans la boîte de dialogue de mise à jour déclenche l'unique autre requête réseau de l'application : un GET pour le fichier de mise à jour lui-même. Comme la vérification, cela n'arrive que parce que vous l'avez demandé.
  • Une fois le téléchargement terminé, l'application le compare au SHA-256 indiqué dans ce fichier JSON. En cas de non-correspondance, le fichier est supprimé et l'installation ne démarre pas.
  • Seul un fichier vérifié est transmis au PackageInstaller d'Android. L'écran de confirmation qui suit est dessiné par Android, pas par Markleaf. Cette étape nécessite la permission REQUEST_INSTALL_PACKAGES ; si elle n'est pas encore accordée, l'application vous emmène d'abord dans les réglages.
  • Si le téléchargement ou la vérification échoue, vous pouvez réessayer, ou l'ouvrir dans votre navigateur comme auparavant.
  • La requête ne transporte que cette URL et des en-têtes HTTP standard. Pas de chaîne de requête, pas de cookie, pas de compte.
  • Ni le contenu des notes, ni les titres, étiquettes, pièces jointes, noms de fichiers, métadonnées, identifiants d'appareil ou données d'usage ne sont envoyés. Cela vaut sans exception dans toutes les versions et pour chacune de ces requêtes.
  • Les versions des boutiques ne contiennent ni la permission ni le code correspondant — non pas désactivés, mais tout simplement absents.

Où sont stockées les données

  • Le contenu des notes, les titres et l'index des étiquettes sont stockés dans la base de données Room interne de l'application.
  • Les paramètres utilisateur sont stockés dans DataStore.
  • Les images jointes sont copiées dans le stockage interne de l'application, les métadonnées EXIF sensibles étant supprimées lors de l'enregistrement.

Politique de sauvegarde du système Android

Markleaf définit android:allowBackup="false" pour exclure les données de l'application de la sauvegarde automatique Android et du transfert d'appareil à appareil. Si vous devez passer à un nouvel appareil ou utiliser plusieurs appareils, c'est vous qui choisissez l'export Markdown, le partage, ou un miroir de dossier SAF.

Mouvement de données initié par l'utilisateur

Les actions suivantes ne se produisent que lorsque vous les effectuez vous-même, via la boîte de dialogue de permission explicite d'Android ou un choix que vous faites dans l'interface.

  • Exporter une note ou toutes les notes au format Markdown (.md)
  • Partager le texte d'une note ou des fichiers via la feuille de partage du système Android
  • Appuyer sur un lien externe dans le corps du texte pour le déléguer au système / au navigateur par défaut
  • Copier dans le presse-papiers
  • Refléter les fichiers Markdown dans un dossier SAF de votre choix

La synchronisation d'un dossier SAF par un client de synchronisation externe comme Drive, Dropbox, OneDrive, Syncthing ou un montage NAS relève de la responsabilité de cette application externe. Markleaf n'effectue pas cette synchronisation lui-même.

Autorisations

La seule permission de type runtime que déclare Markleaf est android.permission.VIBRATE pour le retour haptique. Aucune version ne déclare de permission de localisation, microphone, appareil photo, contacts, notifications, lecture du stockage externe ou lecture des médias. Ni android.permission.INTERNET ni android.permission.REQUEST_INSTALL_PACKAGES n'est présente dans les versions F-Droid et Google Play. Les deux ne sont présentes que dans la version sideload, pour la vérification de mise à jour et l'installation optionnelle décrites à la section Réseau.

Contact

Pour toute question ou signalement de sécurité/confidentialité, contactez-nous via GitHub Issues.

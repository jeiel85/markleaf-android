Follow-up fix to 2.28.2. Markleaf reads the beginning of each file in your sync folder to work out which note it belongs to. A file whose metadata header ran past that point looked exactly like a file with no header, and the file-matching added in 2.28.2 could then overwrite it. Markleaf now keeps reading while a header is still open, and leaves the file alone if it cannot find the end. Only files carrying a large header from another tool were affected.

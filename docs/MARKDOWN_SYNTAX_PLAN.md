# Markdown Syntax Coverage Plan

## Date
2026-10-01 (기준: github/main `b0a26963`, v2.58.0)

## 질문
Markleaf는 Markdown 문법을 빠짐없이 지원하고 있는가. 빠진 것이 있다면 무엇부터, 어떤 순서로
메우는가.

## Conclusion

- **CommonMark 코어와 GFM의 "파싱"은 거의 다 된다.** commonmark-java 0.24.0 + 확장 5개(front
  matter·취소선·각주·작업 목록·표)를 쓰므로, 문법을 *읽는* 쪽의 누락은 GFM autolink(맨 URL)
  하나뿐이다. 그 밖의 표준 문법은 파서가 정확히 인식한다.
- **문제는 파싱 뒤, 프리뷰 어댑터가 AST를 행(row)으로 펼치는 단계다.** 인용문 안의 코드 블록,
  `<div>` 같은 HTML 블록은 **프리뷰에서 통째로 사라진다.** 노트에 쓴 내용이 읽기 화면에 안
  보이는 것이므로 기능 추가가 아니라 버그로 다룬다(M1).
- 표면이 셋이고 서로 다르게 동작한다: **프리뷰**(`CommonMarkPreviewAdapter`), **에디터 라이브
  하이라이트**(`MarkdownSyntaxHighlighter`, 정규식 11개), **PDF 내보내기**(`ExportPdf`, 별도
  파서 + `HtmlRenderer`). PDF는 front matter 확장이 빠져 있어 front matter가 **큰 H2 제목으로
  인쇄된다.**
- commonmark-java는 0.30.0까지 나와 있고 **GFM alerts(콜아웃) 확장, autolink, 병적 입력에 대한
  스택 오버플로·이차 시간 수정**이 들어 있다. 콜아웃 손파싱과 `StackOverflowError` catch를
  정리할 근거가 된다(M2).
- 비표준 확장(`==하이라이트==`, 수식, Mermaid 등)은 제품 결정이다. 권고는 하이라이트만 도입,
  나머지는 하지 않음. 단, **D024가 "수식을 로컬로 보여준다"고 적고 있지만 현재 코드에 수식
  처리는 없다** — 기록부터 바로잡는다.
- Status: **M1–M4 완료(2026-10-01).** Q1–Q4는 권고안대로 확정(D081) — 비표준 확장(M5)은 하지
  않았다. M1 v2.59.1(#491), M2 v2.60.0(#492, commonmark 0.30 — D082), M3 v2.61.0(#494),
  M4 v2.62.0(#496).
  남은 개선점(콜아웃 안 인용 막대 위치, HTML 엔티티 표, PDF 제목 앵커)은 #262에 있다.

## 확인 방법

추측이 아니라 실행 결과다. 엣지 케이스 57개를 `SimpleMarkdownPreview.parse`와
`ExportPdf.renderDocument`에 통과시키는 임시 JVM 테스트를 돌려 출력 행을 확인했다(테스트는
커밋하지 않음). 에디터 하이라이트는 정규식이 결정적이라 코드로 판단했다.

## 현황 — 무엇이 되고 무엇이 안 되는가

### 되는 것 (프리뷰 기준, 실행 확인)

ATX/Setext 제목 H1–H6 · 굵게/기울임/굵은기울임 · 취소선(`~~`, GFM의 `~`) · 인라인 코드 ·
펜스 코드(``` 와 `~~~`, 언어 10종 구문 강조) · 들여쓰기 코드 · 순서/비순서 목록(시작 번호, `)`
구분자, 중첩, loose/tight) · 작업 목록(`-`/`*`, 탭으로 토글) · 인용문 · 수평선 3종 · 표(정렬,
선행 파이프 생략, `\|` 이스케이프, 셀 안 인라인) · 링크(인라인, 참조형, `<autolink>`) · 이미지
(단독 문단, 참조형) · 백슬래시/두 칸 강제 줄바꿈 · 이스케이프·HTML 엔티티 · 각주 · YAML front
matter · GitHub 콜아웃 5종(+미지원 타입은 원문 라벨로 표시) · `<details>` 접기 · 위키링크
`[[ ]]` · 로컬 `.md` 링크.

## 계획

각 M은 단독 PR이고 각자 출시 가능하다. 렌더링이 바뀌는 PR은 Roborazzi 골든을 CI(Linux)
`record_roborazzi`로 재기록하고, 프리뷰 변경은 에뮬레이터/실기기에서 확인한다.

### M1. 내용이 사라지는 것부터 막는다 (P0, 버그 수정 — patch)

사용자 문제: 쓴 내용이 읽기 화면·PDF에서 안 보인다.

- **인용문을 재귀 렌더**: `renderBlockQuote`가 자식마다 `collectText`로 평탄화하던 것을
  `renderBlock` 재귀로 바꾸고, 행에 인용 깊이(`quoteDepth`)를 실어 렌더러가 왼쪽 막대를 그리게
  한다. A1·A5·A6이 함께 해소된다. 기존 `depth`(목록 들여쓰기)와는 별도 필드 — 섞으면 인용과
  목록 들여쓰기가 구분되지 않는다.
- **콜아웃도 같은 방식으로**: 헤더 행 + 본문을 일반 행으로 내고 렌더러가 상자를 행에 걸쳐
  그린다. A1(콜아웃 안 코드)과 A8(링크·굵게·목록 소실)이 여기서 함께 해소된다.
- **HTML 블록 폴백**: `<details>` 외 `HtmlBlock`은 태그를 벗긴 텍스트를 BODY 행으로 낸다
  (이미 있는 `emitPlainHtmlBlockText` 재사용). 주석 블록만 계속 숨긴다. HTML을 *렌더*하지는
  않는다 — 텍스트를 잃지 않는 것이 목표.
- **인라인 HTML**: `<br>`(대소문자·`<br/>` 포함)은 줄바꿈 세그먼트로. 나머지 태그는 지금처럼
  버리되 텍스트 유지(A3).
- **문단 속 이미지**: 이미지를 만나면 문단을 그 지점에서 나눠 텍스트 행 / IMAGE 행 / 텍스트 행
  으로 낸다(Q2). 목록 항목 안 이미지는 depth+1 IMAGE 행.
- **PDF front matter**: `ExportPdf`에 `YamlFrontMatterExtension`을 넣고 front matter는
  인쇄하지 않는다(X1). 장기적으로 프리뷰와 PDF가 확장 목록을 공유하도록 한 곳에 둔다.
- 테스트: 위 표의 입력 각각을 `CommonMarkPreviewAdapter` 단위 테스트로 고정(현재 결과가 아니라
  기대 결과로), `ExportPdfTest`에 front matter 케이스.

### M2. commonmark-java 0.24 → 0.30 + 확장 정비 (minor, 의존성 결정 기록 필요)

사용자 문제: 맨 URL이 링크가 안 되고, 콜아웃 안 서식·링크가 죽는다.

- 업그레이드 근거: 0.27 autolink 유형 설정, 0.28–0.29 **GFM alerts**(사용자 제목, 중첩, 타입
  재정의), 0.30 병적 입력의 스택 오버플로·이차 시간 수정과 `maxOpenBlockParsers`(기본 100)·
  `maxInlineNesting`. 라이선스 BSD-2 유지, autolink 의존성 `org.nibor.autolink` 0.11.0은
  MIT·20KB — F-Droid 문제 없음. Java 11 바이트코드.
- 주의할 변경: 0.30 표 `maxCells` 초과 시 **예외를 던진다** → `parse`의 폴백이 이를 잡아야
  한다. 0.25 표가 앞 빈 줄 없이도 파싱됨(GitHub과 일치 — 기존 노트 렌더가 바뀔 수 있음).
- **autolink**(A10·X4): `AutolinkExtension` — URL·WWW·EMAIL. 프리뷰와 PDF 모두.
- **콜아웃 마무리**: 본문 구조화는 M1에서 끝났다. alerts 확장은 쓰지 않는다 — 허용 타입을
  미리 나열해야 해서, 지금처럼 아무 `[!word]`나 콜아웃으로 보이는 동작이 깨진다(D081).
  대신 헤드 줄의 나머지를 **사용자 제목**으로(`[!TIP] 제목`), Obsidian 접기 표식 `-`/`+`는
  본문에 새지 않게 떼어 낸다. PDF는 콜아웃을 상자로(X2), 위키링크는 라벨 글자로(X3) 인쇄한다.
- **깊이 방어 정리**: `maxOpenBlockParsers`가 블록 중첩을 파서 단에서 막으므로
  `MAX_BLOCK_DEPTH`와 `StackOverflowError` catch를 재평가한다. catch는 다른 경로 보호를 위해
  남기되, 근거 주석을 새 동작에 맞게 고친다.
- `.agent/decisions.md`에 의존성 결정(새 D번호)과 **D024 정정**(수식 처리 없음)을 기록.

### M3. 상호작용 (minor)

- **순서 목록 작업**(A7): `1. [ ]`에 체크박스를 그리고 탭 토글. `toggleTaskAtLine`이 순서
  목록 줄도 처리하는지 확인·보강.
- **문서 내 앵커**(A9): `#slug` 링크는 브라우저로 보내지 않고 프리뷰를 해당 제목으로 스크롤.
  slug는 GitHub 규칙(소문자, 공백→`-`, 구두점 제거, 중복 시 `-1`)을 따른다. 맞는 제목이 없으면
  아무 일도 하지 않는다 — 지금처럼 깨진 URL을 여는 것보다 낫다.

### M4. 에디터 하이라이트 정합 (minor)

- E1: 체크박스 정규식을 `^[ \t]*(?:[-*+]|\d+[.)])\s\[[ xX]]`로 확장.
- E2·E3: 펜스 범위(``` 와 `~~~`)를 먼저 구하고 인라인 패스가 그 범위와 인라인 코드 범위를
  건너뛰게 한다.
- E4: `__굵게__`·`***`·위키링크·맨 URL 강조. 이미지·목록 마커는 시각 이득이 작아 보류.
- 제약: span 수가 늘면 `MAX_SPAN_COUNT`(1,500, #437) 예산에 더 빨리 닿는다. 범위 건너뛰기는
  오히려 span을 줄이지만, E4 추가분은 `MarkdownSyntaxHighlightCostTest`로 측정해 예산을
  넘기지 않는 범위만 넣는다.

### M5. 비표준 확장 — 제품 결정 후 (Q1, Q4)

- **`==하이라이트==` (권고: 도입)**: Bear·Obsidian·Typora가 쓰는 문법이고 Markleaf가 Bear에서
  영감을 받은 앱이라 사용자 기대가 있다. 다른 도구에선 `==`가 글자로 남을 뿐 데이터는
  손상되지 않는다(§2.3 라운드트립 충족). commonmark-java의 사용자 정의
  `DelimiterProcessor`로 구현(ins 확장과 같은 방식) → 프리뷰 `HIGHLIGHT` 세그먼트, 에디터
  배경색, PDF `<mark>`, 서식 툴바/슬래시 명령 항목.
- **수식 (권고: 렌더하지 않음, 기록만 정정)**: 제대로 하려면 KaTeX(WebView+JS)가 필요하고 #71이
  같은 이유로 not planned. `$…$`만 고정폭으로 칠하는 싼 방법은 `$5와 $10` 같은 통화 표기에서
  오탐한다.
- **하지 않음**: Mermaid(WebView+JS), 이모지 단축코드(유니코드 이모지 입력으로 충분), 아래·
  위첨자·`++삽입++`·정의 목록·제목 ID·약어(GFM에도 없고 다른 도구 호환성 낮음), raw HTML
  완전 렌더(보안·복잡도 — M1의 텍스트 폴백까지만).

Datenschutzerklärung von Markleaf

Zuletzt aktualisiert: 26. Mai 2026 · Gilt für Markleaf Android v2.x

Kernprinzip

Markleaf ist eine local-first Markdown-Notiz-App. Sie betreibt keinen eigenen Server und lädt Notizen, Tags, Anhänge oder Metadaten niemals auf einen externen Server hoch. Die über F-Droid und Google Play verteilten Builds besitzen überhaupt keine android.permission.INTERNET-Berechtigung; der Sideload-Build auf GitHub Releases deklariert sie für genau einen Zweck, beschrieben unter Netzwerk.

Informationen, die Markleaf nicht erfasst

  • Name, E-Mail, Kontakte, Standort
  • Konto- oder Anmeldeinformationen
  • Notiztext, Titel, Tags, angehängte Bilder, Dateinamen, Metadaten
  • Nutzungsstatistiken, Telemetrie, Analyse-Ereignisse, Werbe-IDs
  • Absturzberichte oder Gerätekennungen

Markleaf enthält außerdem keine Analyse-, Werbe-, Tracking-, Remote-Config-, Firebase- oder Closed-Source-Absturzbericht-SDKs.

Netzwerk

Das hängt davon ab, woher du die App hast. In beiden Fällen werden keinerlei Notizdaten gesendet.

  • F-Droid und Google Play — keine android.permission.INTERNET-Berechtigung und überhaupt keine Netzwerkaktivität.
  • GitHub Releases (Sideload) — deklariert zwei Berechtigungen: eine für die Update-Prüfung und eine, damit das von dir heruntergeladene Update installiert werden kann. Beide laufen nur, wenn du die Prüfung einschaltest.
F-Droid / Google Play   INTERNET: keine · REQUEST_INSTALL_PACKAGES: keine
GitHub Releases         INTERNET: Update-Prüfung · REQUEST_INSTALL_PACKAGES: Installation nach SHA-256-Prüfung

Die Update-Prüfung im Sideload-Build

  • Standardmäßig aus. Es passiert nichts, bis du sie in den Einstellungen einschaltest.
  • Einmal täglich ein einziges GET auf eine statische JSON-Datei, die die neueste Version beschreibt. Eine fehlgeschlagene Prüfung wird stillschweigend übergangen.
  • Tippst du im Update-Dialog auf Herunterladen und installieren, löst das die einzige weitere Netzwerkanfrage der App aus: ein GET für die Update-Datei selbst. Wie die Prüfung geschieht das nur, weil du es verlangt hast.
  • Nach dem Download vergleicht die App die Datei mit dem SHA-256 aus dieser JSON-Datei. Stimmt er nicht überein, wird die Datei gelöscht und die Installation beginnt nicht.
  • Nur eine geprüfte Datei wird an Androids eigenen PackageInstaller übergeben. Der anschließende Bestätigungsbildschirm wird von Android gezeichnet, nicht von Markleaf. Dieser Schritt braucht die Berechtigung REQUEST_INSTALL_PACKAGES; fehlt sie noch, führt dich die App zuerst zu den Einstellungen.
  • Schlagen Download oder Prüfung fehl, kannst du es erneut versuchen oder es wie zuvor im Browser öffnen.
  • Die Anfrage enthält nur diese URL und übliche HTTP-Header. Kein Query-String, kein Cookie, kein Konto.
  • Notizinhalte, Titel, Tags, Anhänge, Dateinamen, Metadaten, Gerätekennungen und Nutzungsdaten werden nicht gesendet. Das gilt ausnahmslos in jedem Build und bei jeder dieser Anfragen.
  • Die Store-Builds enthalten weder die Berechtigung noch den Code dafür — nicht deaktiviert, sondern gar nicht erst eingebaut.

Wo Daten gespeichert werden

  • Notiztexte, Titel und der Tag-Index werden in der internen Room-Datenbank der App gespeichert.
  • Benutzereinstellungen werden in DataStore gespeichert.
  • Angehängte Bilder werden in den internen Speicher der App kopiert, wobei sensible EXIF-Metadaten beim Speichern entfernt werden.

Android-System-Backup-Richtlinie

Markleaf setzt android:allowBackup="false", um App-Daten von Android Auto Backup und der Geräte-zu-Geräte-Übertragung auszuschließen. Wenn du auf ein neues Gerät wechseln oder mehrere Geräte nutzen möchtest, wählst du selbst Markdown-Export, Teilen oder eine SAF-Ordner-Spiegelung.

Von dir ausgelöste Datenbewegung

Die folgenden Aktionen finden nur statt, wenn du sie selbst ausführst, und zwar über Androids expliziten Berechtigungsdialog oder eine von dir getroffene UI-Auswahl.

  • Eine einzelne Notiz oder alle Notizen als Markdown (.md) exportieren
  • Notiztext oder Dateien über das Android-System-Share-Sheet teilen
  • Auf einen externen Link im Text tippen, um an das OS / den Standardbrowser zu delegieren
  • In die Zwischenablage kopieren
  • Markdown-Dateien in einen von dir gewählten SAF-Ordner spiegeln

Ob ein SAF-Ordner von einem externen Sync-Client wie Drive, Dropbox, OneDrive, Syncthing oder einem NAS-Mount synchronisiert wird, liegt in der Verantwortung dieser externen App. Markleaf führt diese Synchronisierung nicht selbst durch.

Berechtigungen

Die einzige Berechtigung mit Laufzeitcharakter, die Markleaf deklariert, ist android.permission.VIBRATE für haptisches Feedback. Kein Build deklariert Berechtigungen für Standort, Mikrofon, Kamera, Kontakte, Benachrichtigungen, Lesen des externen Speichers oder Lesen von Medien. Weder android.permission.INTERNET noch android.permission.REQUEST_INSTALL_PACKAGES ist in den F-Droid- und Google-Play-Builds vorhanden. Beide gibt es nur im Sideload-Build, für die unter Netzwerk beschriebene Update-Prüfung und die optionale Installation.
